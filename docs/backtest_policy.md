# 時系列検証・公式払戻による損益評価の方針

## Version 0.2の単勝MVP

固定済みの購入判断を [既存HRへ直接結合して精算する経路](v02_hr_settlement.md)を追加しました。元台帳・policyのハッシュを検証し、選択をやり直さず精算項目だけを更新します。既存HR形式分類・金額対応を再利用し、通常条件の単一HR1/2と確認済み単位を持つレースだけを精算します。今回範囲の単位・版レビューを全期間へ自動拡張しません。

[Version 0.2](version_0_2.md)では単勝専用モジュールを追加しました。判断は観測/発表時刻とも判断時刻以前の最新スナップショット、時点確認済みの予定時刻・全頭名簿で行います。既定は10分前JST・p×オッズ−1≧0.05・最大1点100円。取得不能なレースも全対象の取得率母数に残します。

本人承認済みの [発表時刻基準モード](v02_publication_run.md)を別policyで追加しました。実取得時刻はnull、実購入可能性・通信遅延は未検証と記録し、暫定的な事後シミュレーションに限定します。区分1中間オッズの発表分の終端までが判断以前のものだけを使い、分境界を推測しません。自動の予定時刻は開催日前作成の区分2出馬表・変更なし・区分2名簿を組み合わせた当初予定に限定し、作成日だけで時点を認定しません。発表履歴の対応率をPC実取得率と呼びません。既定の実観測モードは変更しません。

精算は通常最終版・100円あたり公式公表額・全的中対象が確認できるレースだけです。確認済みのローカル公式参照ファイル、または年/場/単位/版/成立条件を明示レビューしたHR対応表を使用します。特殊・返還・訂正等の未解決はレース単位の保留とし、他の確認済み通常単勝を止めません。未精算を含む月の全体利益はnull、精算済み部分と共通条件の比較を別掲します。表示オッズで将来の払戻を計算しません。

確率のレース内正規化は事前固定変換、任意の温度校正はモデル早期終了期間とも最終テストとも異なる検証期間でのみ選択します。閾値の自動最適化は行わず、実行前に固定したpolicyを使用。1番人気は同じ時点の価格から決め、正常精算できる同じレース集合とAI購入部分集合で比較します。既知の旧テスト期間を再利用した結果は記述的バックテストです。以下はPhase 1/Version 0.1時点の方針記録です。

文書日：2026-10-15（Asia/Tokyo）。Phase 1.3の架空仮想決済に加え、Phase 2.0で [Version 0.1](version_0_1.md) の時系列LightGBM・暫定着順ラベル評価・購入時点価格による仮想判断を実装しました。実HR金額展開と実レース損益の確定は保留します。

v0.1は学習/検証/最終テストを日付で分離し、カテゴリ辞書・基準確率を学習期間だけで計算します。検証期間は早期終了専用、最終テストは評価専用です。Log Loss、Brier、信頼度ビン、ECEを2種類のベースラインと比較します。購入方針は学習前に固定して保存し、最終テストの結果を見て変更しません。購入時点の単一価格がなければ見送り、複勝の範囲価格も保留します。購入数・予定投資額・期待値分布は集計でき、公式金額と特殊ケース未確認時の払戻・ROI・純損益はnullです。

前向き予測と過去バックテストは台帳のmodeで区別します。前向きは本人PCの現在時刻で発走前を確認し、新規ファイルへ排他的に保存します。後の結果照合は別ファイルで行い、凍結した予測を書き換えません。SHA-256とread-only属性は誤更新防止・改変検出であり、第三者の時刻証明ではありません。

Phase 1.4のHR形式分類は、空白の未使用枠・通常形式候補・00/ゼロ値の要確認枠を区別します。形式正常や全枠受領だけで、的中ラベル・通常不的中・成立/発売状態・決済可能を確定しません。金額単位・特殊払戻・訂正削除の確認ゲートは閉じたままです。詳細は [payout_formats.md](payout_formats.md)。

Phase 1.5の [ローカル照合](payout_reconciliation.md) は本人が用意した公式公表額と少数HRの金額仮説を比較する検証だけです。一致は選択した年・券種・ケース・確認条件の証拠に留まり、金額単位の自動承認や本番決済の許可にはしません。プラス10は公表額を直接比較し、最終オッズから金額を作りません。00/2着払い・特殊払戻・版の未確認を除外して全体収益を確定することも禁止します。

Phase 1.5.1のH1必須モードでは、H1とHRの6列キー・独立した区分/版・発売/成立条件を検査します。H1欠損や複数版を結合で落とさず保留し、整合した通常条件だけを金額仮説比較の候補にします。着払キー2は参照条件と一致する通常の数値対象に限り比較でき、00の解決や特例決済は開放しません。H1の事後確定情報も当該レースの予測特徴量に混ぜません。

実単位・フラグ・的中対象・時点対応は `needs_confirmation`。HRと今回結果・確定オッズは `prohibited_feature`。`confirmed` の対応は仕様とPC-KEIBAの構造を確認した後にのみ登録します。

## 1. 事前判断と事後評価を分離

| 処理 | 状態 | 使用情報 |
|---|---|---|
| 予測 | proposed | tまでに入手可能な特徴量と、その時点までに構築したモデル/校正器 |
| 購入判断 | proposed | 予測確率、t以前のレース前オッズ、発売状態、資金上限。HRや最終オッズを参照しない |
| 決済 | needs_confirmation | 正規化した公式HRと対象投票の対応。通常払戻/返還/特払等を別状態で扱う |
| 事後評価 | proposed | 凍結した事前判断台帳と、公式決済台帳を結合。決済値から事前ルールを作り直さない |

依頼文ではO1区分5は確定（月曜）オッズです。これしかない場合、予測時点での購入判断・期待値・月間利益の検証は開始不可です。HRによる決済や確率評価の仕様確認とは区別します。

### Phase 1.3の実装範囲

`settlement.py` の金額決済は、明示したSYNTHETIC・JPY_PER_100・finalと必要な時点/対象情報が揃う架空入力だけです。既定のHR_UNCONFIRMEDは、単位を手動指定しても的中・不的中・返還の金額を返しません。`payout_decoder.py` の意味/単位ゲートも閉じたままです。

正常入力の通常的中・同着は対象ごとの払戻額×購入単位数、不的中は0円、返還は投資額、純損益は払戻額−投資額です。公式b列の単位を認定したものではありません。特払・不成立・発売なし・中止・未確定・不正は別状態と固定理由を返し、払戻・損益はNoneとします。詳細な契約は [settlement_api.md](settlement_api.md)。

## 2. 時系列分割（proposed）

1. 年別収録・HR対応・特徴量の時点履歴・欠損を確認してから分割年を提案する。現在は年境界を固定しない。
2. 過去期間を学習、次の期間を検証、さらに未来の未使用期間を最終テストとする。ランダムな馬行分割は採用しない。
3. 6列レースキーでgroup化し、同じレースの全馬・複数予測時点を同じ分割へ入れる。分割境界はレース時刻で決める。
4. 各ウォークフォワードfoldの学習期間より先のラベルをモデル/校正/閾値fitへ使わない。結果の公開遅延があるなら、利用可能時点を満たす間隔を設ける。
5. 欠損補完・カテゴリ辞書・校正器・選択閾値は学習/検証の許可範囲だけでfitする。最終テスト期間の分布や結果で最適化しない。
6. 予測時点tの過去成績集計には、t以前に実際に確定/公表された結果だけを利用する。過去の検証レースがtまでに確定していれば実運用と同じ因果的更新を許す案だが、将来の全期間統計を一括joinしない。
7. 最終テストを開く前に特徴量・分割・校正・購入ルール・資金ルールを凍結する。結果を見て繰返し調整しない。変更した場合は新しい将来期間が必要。

学習・校正・購入判断の期間とバージョンを別に記録します。同一レースの事後情報をそのレースの別の予測時点へ混ぜません。ブートストラップ等の不確実性評価も馬行を独立と見なさず、レース/日等のまとまりを考慮する案です。

## 3. 標準ラベルと特殊ケース

| ケース | 状態 | 標準的中ラベル/確率指標 | 決済台帳の扱い |
|---|---|---|---|
| 通常単勝 | proposed | 公式単勝対象集合への所属0/1 | ordinary_win、公式HRの対応金額 |
| 通常複勝 | proposed | 公式複勝対象集合への所属0/1。3着以内の固定規則は不可 | ordinary_place、公式HRの対応金額 |
| 単勝同着 | proposed | 複数の公式対象を各々1。単勝最大3組の参照仕様と展開を確認 | ordinary_win_dead_heat、対象ごとの公式払戻 |
| 複勝同着 | proposed | 複数の公式対象を保持。最大5組の参照仕様と頭数条件を確認 | ordinary_place_dead_heat、対象ごとの公式払戻 |
| 出走取消・競走除外・発走除外等の返還 | needs_confirmation | 当該券種/投票はNULL・標準評価対象外。非的中0にしない | refund、返還対象・金額の公式規則を別記録 |
| レース中止 | needs_confirmation | 標準ラベルなし | cancelled、購入済み票の公式処理を確認 |
| 投票法の不成立 | needs_confirmation | 標準ラベルなし | not_established。自動的に通常返還へ統合しない |
| 特払 | needs_confirmation | 標準的中の1/0とは別に評価 | special_payment。的中対象と支払条件を独立に確認 |
| 発売なし | needs_confirmation | 予測/ラベル対象の方針を確認。投票を作らない | not_offered、購入不可として記録 |
| 欠損・初期値・不正・未対応 | needs_confirmation | NULL・未解決。0埋めしない | unresolved_*。金額を0として収益へ混ぜない |

標準確率評価と現金収支の母集団は異なります。返還・特払を確率指標から除外しても、購入済み票の現金収支を都合よく除去しません。台帳では原則として全判断を残し、未解決の件数・投入資金を分けます。

`payout_policy.py` は実HRの未確定な対応方針を保持し、既存のnot_implementedはこの実HR適用を指します。Phase 1.2の [refund_targets.md](refund_targets.md) を使い、Phase 1.3では架空入力の返還を検証します。実フラグの優先関係・HR払戻の意味変換・本番の返還金額適用は未実装です。

## 4. 予測性能

以下は `proposed`。券種ごとの同じ標準評価マスクで計測し、件数・除外理由を添えます。

| 指標 | 定義・診断 |
|---|---|
| Log Loss | -mean(y log(p) + (1-y) log(1-p))。計算上のclip幅を事前に固定し、校正を変更する口実にしない |
| Brier Score | mean((p-y)^2) |
| 確率校正 | 信頼度曲線・校正binの件数・券種/頭数/期間別の偏り。校正器は最終テストでfitしない |
| レース単位の整合性 | 0≤p≤1、同じ対象馬の重複なし。sum(p)は公式的中対象数の条件付き期待値に対応する診断 |
| 対象と平均の公平性 | 馬単位の平均とレースごとの平均を併記。欠損や対象頭数差で有利な母集団を作らない |

同着では単勝の的中対象が複数になり得ます。常にsum(p_win)=1と強制しません。複勝も頭数・成立条件・同着で対象数が変わるため、sum(p_place)=3や単純なtop3を強制しません。特例を除いた通常条件での偏りは別に診断します。

## 5. 投資・払戻・月間純利益

| 項目 | 状態 | 方針 |
|---|---|---|
| 金額単位U | needs_confirmation | 公式HRの金額が何購入単位あたりかを確認。架空APIの100円単位とHRのb列の対応を仮定しない |
| 払戻基準 | needs_confirmation | 公式HRに基づく的中対象と金額。確定オッズから再計算しない |
| 通常払戻 | proposed | 単位を確認した後、公式の1単位払戻×購入単位数。丸めや端数をオッズから推測しない |
| 返還・特払・不成立 | needs_confirmation | 各公式規則・金額・対象を独立に確認。通常的中/通常非的中の式を流用しない |
| 事前期待値 | proposed | E[払戻・返還等の総受取｜I(t),投票案]−投入額−適用費用。事後HRで算出した利益は事前EVではない |
| 単勝の簡略式 | proposed | 通常成立のみ・確認済みgross oddsなら投入額×(p×O_t−1)。返還/特払等を含む無条件期待値として流用しない |
| 複勝の事前EV | needs_confirmation | オッズ幅の扱い・的中条件下の払戻分布が必要。上限や最終値を使わない。下限による保守的代理値も真の期待値と区別 |
| 月間目的 | proposed | 月間期待純利益を資金/損失制約内で評価。月ごとの実現純利益も別に表示 |

金額を読み取れないHR、未対応の特例、当時オッズ欠如があるまま0円や最終値で埋めて、事前戦略の収益を確定しません。

## 6. 収益指標（proposed）

| 指標 | 定義 |
|---|---|
| 仮想購入件数 | 有効な判断に対して実際に生成した投票数。レース数・対象馬数も別記 |
| 投資総額 | 全購入票の投入額。返還票の投入も含む |
| 払戻総額 | 公式HRに基づく通常払戻＋確認済み返還/特払等の受取。種類別も分ける |
| 純損益 | 仮想決済APIは総受取−投資総額。将来費用を評価する場合は費用項目と控除後利益を別に管理し、APIの意味を黙って変えない |
| 回収率 | 総受取/投資総額。投入0なら未定義として表示。通常払戻のみの比率も別に診断 |
| 月別純損益 | JSTの開催月に帰属させる実現成績と、実際の入出金月の資金推移を区別 |
| 最大ドローダウン | 固定した初期資金・評価間隔による資金曲線の最高値からの最大低下。金額と率を報告 |
| 購入見送り率 | tで購入判断が可能だった候補のうち購入しなかった割合。発売なし等の対象外と区別 |
| 券種別成績 | 単勝・複勝別の上記指標、返還/特払/未解決の件数・資金 |

月間期待値と実現月間利益を混同しません。資金曲線では未決済の投入・拘束資金を含む利用可能残高と、実現損益残高を分ける案です。未解決決済が残る場合、全体純利益を確定済みと表示しません。

Phase 1.3の `summarize_settlements()` は重複投票を拒否し、保留があれば全体の払戻総額・純損益をNoneにします。空バッチも利益を確定しません。月別は全体のticket_ref一意性を確認してからJST開催月で分ける設計で、月が不明な未配賦票を除去しません。実月別集計は行っていません。

## 7. 資金・リスク・再現性

すべて `proposed`、具体的な上限金額・割合・初期資金は `needs_confirmation` です。

- 1票・1馬・1レース・1日・月間の投入上限、最大損失許容、最低残高、同時拘束資金を設定する。
- 賭け金は確認した購入単位の整数倍。上限超過や資金不足なら見送る。損失後の倍賭けや無制限な賭け金増加は採用しない。
- 同一レースの単勝/複勝や複数馬は相関する。独立と仮定したリスク縮小や個別EVの足し算だけで配分を決めない。
- 最大ドローダウン、月間損失、賭け金集中、オッズ変動、校正誤差に対する感度を検証期間で評価し、最終テスト前に方針を固定する。
- 単位賭けの基準戦略と資金配分戦略を別に評価し、大きな投入だけで利益が増えた場合を区別する。
- 校正・購入閾値・賭け金の探索回数と候補を記録し、最終テストへの繰返し適合を防ぐ。

データ範囲、仕様版、特徴量registry版、予測policy、split、モデル/校正器版、判断台帳、決済版をローカルで記録します。実データを含む台帳・特徴量・モデル評価成果物をOneDriveやGitへ追加しません。
