# Phase 1で確定できない項目

Phase 1.1では依頼文にHR仕様の一部が提示されました。仕様原本とPC-KEIBAの列定義の照合は未実施です。外部通信は禁止されているため、実装中にWebへアクセスしていません。実データや秘密を共有せず、利用者がローカルで資料を確認する前提です。

| 対象 | 現段階の候補 | 必要な確認 |
|---|---|---|
| jvd_ra | レース条件、実施/中止の判定 | 区分列、更新時点、変更履歴、キー表現 |
| jvd_se | 出走情報、着順等のラベル候補 | 馬単位キー、特殊結果、取消・除外・同着、版/時点 |
| jvd_o1 | 単勝・複勝オッズの候補 | 格納単位、倍率、欠測コード、発表時点、履歴/上書き |
| jvd_hr | 公式的中対象・決済の照合候補（特徴量禁止） | 区分、繰返し、単位、返還・特払・不成立・発売なしの区別 |
| jvd_ks | 騎手情報の候補 | 過去時点の値が残るか、事後更新/累積値 |
| その他public表 | 仕様確認後に選定 | 情報の意味、レース前の入手可否、事後訂正、履歴 |

作成日時だけでレース前の利用可能性を決めません。確定成績や最終オッズを過去の予測特徴量へ混ぜないため、公開・取得・更新・発走時点と履歴保持を確認します。

キー集合の欠損・重複・型差の確認後に、対象年・競馬場・中止除外・ラベル定義を決定します。Phase 2計画では時系列検証、確率校正、予測時点のオッズによる期待値、月間純利益の評価を扱いますが、今回は学習を実装しません。

最新の仕様案は [phase2_data_contract.md](phase2_data_contract.md)、[phase2_feature_registry.md](phase2_feature_registry.md)、[backtest_policy.md](backtest_policy.md)、[hr_mapping.md](hr_mapping.md) を参照してください。O1区分5は依頼文では確定（月曜）オッズで、予測特徴量・過去の事前購入判断へ使用しません。
