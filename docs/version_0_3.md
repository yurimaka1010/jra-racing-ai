## 実行する処理

1. 固定したVersion 0.2台帳の購入馬について、正規化後の勝率・判断時点オッズ・積・期待利益率をローカルで照合します。表示は分布と不一致件数のみ。`勝率×オッズ−1` の計算は変更しません。
2. RA・SEの必要列だけを完全な6列レースキーで読み、基本特徴量を取り込みます。対象日予測には区分1～7の出走情報を使用し、現在レースの着順・走破タイムをSQL選択とPythonの両方で除きます。学習・履歴は従来どおり区分7です。
3. 2024-01-01から参考日の7日前までの過去走を更新します。共通の `ml.features.build_features` が対象日より前かつレース日+7日以降の結果だけを選び、前走着順・間隔・対象履歴内の過去出走数・平均着順・同距離／同コース成績を計算します。同日・現在・未来の結果は使用しません。
4. 単勝LightGBMだけを新規学習します。設定は既存のbinaryモデルを維持し、最大100ラウンド・早期終了20・カテゴリ定義は学習部分から固定します。未知カテゴリは既存のUNKNOWN扱いです。複勝モデルは再学習しません。
5. 既存の温度選択とレース内正規化を利用します。候補温度0.75・1.0・1.25・2.0を独立した校正期間のレースLog Lossで選びます。期待利益率の上限は設けません。
6. 未使用期間で旧モデル、新モデルT=1、新モデル選択温度を比較します。さらに既知の参考日について、旧シミュレーションと同じオッズ・発走時刻情報・確認済み公式HRを再利用し、新しい予測で仮想購入・精算します。旧購入判断は固定したままです。

過去出走数は指定履歴期間内の有効な着順がある出走数です。生涯出走数を意味しません。新馬・履歴期間より前の出走・着順不明などには欠損が残ります。馬場状態と走破タイムは今回の最小構成で無効のままです。基本項目が全件欠損、または前走着順が全件欠損の場合は、改善済みと誤認して学習を続けず固定理由コードで停止します。

## 期間と評価

| 用途 | 初期期間 | 使用目的 |
|---|---|---|
| モデル学習 | 2025-01-05～01-18 | 旧モデルと同じ144レース規模を基準にする |
| 早期終了 | 2025-01-19 | ブースティング回数選択 |
| 温度校正 | 2025-02-01～02-02 | 温度だけを選択 |
| 未使用の確率評価 | 2025-02-15～02-16 | モデル・温度・閾値選択に使用しない |
| 既知の参考比較 | 固定したVersion 0.2の対象日 | 同じ価格・精算条件で旧判断と比較 |

学習件数を144に強制して切り落とす処理はありません。最新の収録状況に応じた実件数を保存します。校正と早期終了、校正と最終評価の間に7日を超える間隔を要求します。過去走結果が後の評価入力に入る場合も、共通の7日条件を満たすものに限ります。

期間は `--train-start / --train-end / --valid-end / --calibration-start / --calibration-end / --test-start / --test-end` で明示変更できます。評価結果を見て変更した期間は未使用評価と扱わず、次の評価期間を別に確保してください。収益を見て閾値を後付け変更しません。今回の購入方針は発走予定10分前、期待利益率5%以上、1レース最大1点、100円です。

確認する指標は以下です。

- 特徴量別の欠損件数・欠損率、履歴なしの件数。
- 馬単位Log Loss・Brier、レースLog Loss、一様予測との比較、予測1位の的中率・勝馬の平均予測順位。予測同率には同率の配分を使います。
- 1%未満、1～2%、2～5%、5～10%、10～20%、20%以上の確率帯別の予測と観測頻度。
- 温度選択の候補別損失、校正前後、未使用期間での変化。
- 仮想購入・見送り・未精算件数、的中、投資、払戻、純利益、回収率、期待利益率の分布。同じ条件を満たす共通レースで旧AI・新AI・1番人気を比較。

期待利益率の低下だけでは改善と判定しません。既知の参考日の利益だけで温度や特徴量を選び直さず、未使用期間の予測性能を併せて確認します。払戻は公式HRから精算し、判断時点のオッズから再計算しません。

## 保存先と制限

既存APIを再利用するため、各フォルダーで新しいIDを発行します。旧IDのファイルは編集しません。

- `C:\Users\acbd5\AppData\Local\JraRacingAI\ml-v01\schema / datasets / models`：新しい列対応・学習／履歴／出走データ・単勝モデル。
- `C:\Users\acbd5\AppData\Local\JraRacingAI\ml-v02\predictions / policies / simulations`：Version 0.3と記録した新しい予測・方針・台帳・月次集計。個別情報はこのローカル領域のみ。
- `C:\Users\acbd5\AppData\Local\JraRacingAI\ml-v03\evaluations\<ID>\run.json` と `report.md`：匿名の欠損・性能・収益比較。最後のJSONに `run_directory` が表示されます。

保存先は既存の同期フォルダー・ネットワーク・junction等の拒否処理を使います。モデル・主要成果物はハッシュを記録し、新規作成後は読み取り専用にします。これは改ざん不能な保管庫を意味しません。

初期上限は履歴25万行、学習・対象日の各読込2万行、SQL1本60秒、読込全体300秒です。上限超過は途中のデータで学習せず停止します。モデル学習・ファイル生成時間は読込時間制限とは別です。DB認証と列対応確認を待つ時間は読込予算に含めません。

過去時点の完全な訂正履歴は今回復元していません。現在のDBスナップショットからレース前に宣言される列を選び、履歴には7日の遅延を設けますが、全項目の当時の版まで証明したものではありません。JRA発表時刻基準の暫定的な事後シミュレーションであり、実取得時刻・通信遅延・購入可能時刻は未検証です。

## 別日の評価

保存済みモデル・温度・閾値を変えず、本人が選んだ別日の履歴を更新して予測・仮想精算します。実際の `run.json` の絶対パスと日付へ置換してください。

```powershell
& 'C:\Users\acbd5\AppData\Local\JraRacingAI\venv\Scripts\python.exe' -B '.\scripts\run_v03_local.py' evaluate --execute-local --run 'C:\Users\acbd5\AppData\Local\JraRacingAI\ml-v03\evaluations\<ID>\run.json' --race-date 'YYYY-MM-DD'
```

既存の `apd_sokuho_o1` 読込・生形式確認とHR精算を使用します。発売前のRA区分2など発走予定時刻の根拠が取れない場合、結果版の時刻を当時利用可能と推定せず該当レースを保留します。別期間の時系列オッズがなければ見送りを記録します。すでに本人が確認した当時の入力ファイルがある場合は、既存Version 0.2形式の `--schedules '<ローカル絶対パス>' --odds '<ローカル絶対パス>'` を指定できます。

HR金額の確認範囲を新年度・新競馬場へ自動拡大しません。新たな範囲には既存の本人用HR確認が必要です。`--payout-source` はその範囲を実際に確認した既存のローカル設定に限って指定します。不明・特殊・複数版は保留し、通常の確認可能なレースは精算します。別期間が実際に未使用だったかは利用者が管理します。コマンドを実行しただけで新しい最終テストと認定しません。
