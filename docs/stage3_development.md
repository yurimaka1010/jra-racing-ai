## 再利用診断

λ収縮は、保存木の実際のraw scoreを入力キャッシュから計算し、

`race_normalize(sigmoid(logit(q) + λ × raw_score))`

を使用します。正規化済み確率からraw scoreを逆算しません。λ=0は無補正市場、λ=1は元アンカーの保存予測を再現することを検証します。較正期間で選んだλを後続期間へ固定します。ABCD入りのλモデルは同様に調整したmarket_historyとも比較します。

温度は保存木の未較正二値確率にだけ適用し、レース内で正規化します。既に温度適用済みの確率へ再適用しません。主2025分割と年次の結果を独立に保存します。

## OOFと統合層

各年の能力モデルは前年8月末まで学習、前年9月8日〜10月末で早期終了、前年11月8日〜12月24日で較正し、翌年を予測します。カテゴリ辞書も学習期間だけで作成します。2020〜2024年は1〜12月、2025年は1〜9月を生成。保存済み年次予測にない月は推論だけを追加します。7日遅延とStage 2の全履歴母集団を維持します。

OOF CSVは馬単位のentry_key、日付、確率、生成元モデルID、特徴量履歴の最終日を持ちます。生成元一覧にモデルmanifestハッシュ、学習・早期終了・較正期間、カテゴリ作成期限を保存します。読み込み時も年、モデルID、日付、7日遅延、確率の有限性を検証します。

統合スコアは次の4構成だけです。各スコアをレース内Softmaxへ通します。

| 構成 | スコア |
| --- | --- |
| M | a log(q) |
| MH | a log(q) + c h |
| MA | a log(q) + b log(pA) |
| MHA | a log(q) + b log(pA) + c h |

qは既存T−10市場確率、pAは固定したStage 2手順の時系列OOF、hはT−30付近からT−10までの正規化市場確率の対数変化です。早期欠損はh=0で主評価に残しますが、診断メタデータでは欠損と観測された変化0を区別します。公表時刻・経過時間・鮮度・理由は元の市場packetを参照します。履歴完備部分集合の比較も保存します。

共通切片、頭数、人気、欠損フラグ等の補助変数、log(pA/q)の重複項は追加していません。幾何混合はMAのa=1−w、b=wという制約付き特殊形です。

目的関数は、

`平均レース勝馬NLL + strength / 2 × Σ(係数 − 市場基準係数)²`

で、市場基準はa=1、他0です。NumPyと既存SciPyのL-BFGS-B、解析的勾配、最大500反復を使用します。非有限値や最適化失敗はfailedとして記録し、成功候補へ入れません。

統合層は2020年以降のOOFのうち前年8月末までで係数を学習。前年9月8日〜10月末のレースLLで正則化強度を選び、同点は強い正則化を優先します。検証後の再学習はしません。後続の当年1〜9月は設定固定です。

## E群とデータ品質

公式JV-Data仕様書のSE項番61と、PC-KEIBAの `public.jvd_se.time_sa` の対応を確認します。4文字の符号＋3桁、0.1秒単位です。勝馬は2着馬との差を負、他馬は勝馬との差を正で保持します。`-000` / `+000` は有効なゼロ、符号なし初期値 `0000` と無効値 `9999` は欠損です。幅、ASCII、符号と着順の整合を検証し、不明・異常時は欠損にします。

追加は直近タイム差と直近3走加重平均（1/0.5/0.25）の2項目だけです。過去レース日＋7日以降に履歴へ反映し、当該結果は当該特徴量に使いません。勝馬の差を一律0へ置換しません。

補足DB取得は月分割の必要列だけです。元のStage 2と完全キー、馬ID、着順、異常区分、件数を照合します。不一致ならEを見送り、元のラベルや母集団を更新しません。旧特徴量の列名・計算式・カテゴリ辞書は維持してEを末尾に加え、専用format_version=3で保存します。

goingとprevious_time_secondsはStage 2の生成器で意図的にNoneへ固定され、原列も収集対象に含まれていません。元DBの欠損や形式不正が原因だと断定しません。この2列を有効化する実験は今回行いません。

## 候補選択と収支診断

能力更新はStage 2 ABCDに対し、AI統合は凍結する市場情報だけの対照に対し、年次プール差が負かつ3年中2年以上で改善する候補を優先します。候補は各1つまで。区間が0をまたぐ場合は不確実と明記します。市場対照は無補正市場、market_history、そのλ版、M、MHからプールのレースLLで選択し、同点は記載順に簡単な既存構成を優先します。

**収益集計より前**に `selection_before_financial.json` を保存します。利益・ROI・追加購入フィルタをモデル選択に使いません。

主要診断は単勝100円、EV5%以上、最大1点の既存方式です。追加診断はStage 2 ABCD、凍結市場対照、残ったAI統合候補だけへ推定勝率5%以上を適用。EV条件と勝率条件の積集合を先に作り、その中から最大EVを選択します。1番人気は同時点オッズによる機械的対照として、同じ市場・精算可能母集団で併記します。

発走前オッズで購入判断し、確認済みHRの通常公式払戻で精算。未精算は0円へ変換しません。購入0件のROIは未算出です。利益・ROIには開催週5,000反復の区間と購入0件の再標本割合を保存し、分母0の再標本をROI=0に置換しません。100件未満は記述的な少数購入注意を表示します。この件数境界は検定や十分な収益証明の基準ではありません。

最大DDは元の時系列に基づく診断で、bootstrapしていません。月次収支、最大払戻依存、最大払戻を除いた損益、精算済み部分集合も記録します。詳細台帳は選択馬と判断時刻等だけを保存し、全馬の生オッズを方式ごとに繰り返し複製しません。
