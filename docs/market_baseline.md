## オッズの時点と比較対象

対象表は `public.apd_sokuho_o1` と `public.jvd_o1` です。使用列は6列レースキーに加えて `record_id / data_kubun / happyo_tsukihi_jifun / hatsubai_flag_tansho / odds_tansho`。発走前中間オッズがある場合だけ、予定時刻の根拠として既存のRA出馬表確認も利用します。全年度の件数監査や履歴収集を追加しません。

| 集計名 | 採用条件 | 解釈 |
|---|---|---|
| pre_race_publication_time | O1区分1、当初予定発走10分前までに発表分が終了、同じ名簿で価格が揃う | 発表時刻基準の発走前比較。実取得・購入可能時刻は未検証 |
| final_category_5 | O1区分5 | 確定（月曜）の事後参考比較 |
| final_category_4 | 区分5がなく区分4がある | 確定の事後参考比較 |
| final_category_3 | 区分5/4がなく区分3がある | 最終の事後参考比較 |

発走前の集計を先に表示します。確定・最終系も別表に保存します。同じレースが発走前と最終系の双方に入る場合がありますが、時点の違う価格を混ぜて全66レースの1つの指標にはしません。最終系の発表時計は公式定義の対象外なので、作成日や発走時刻を代入しません。区分2の前日最終は今回の最終系の代用にしません。

同区分の表内複数件・異なる価格の競合・削除/中止/未知区分は除外します。2表にある同区分の完全に同じ価格ブロックだけは同一のコピーとして扱います。全訂正履歴を復元する機能ではなく、現在保存された最終系の参考比較です。

欠損、異常値、無投票、上限表示、対象馬の取消記号、出走馬集合不一致はレース全体を除外します。対象にいない馬番の明示的な取消記号だけは除外できます。馬を落としてAIの確率を再計算したり、対象レースを増やしたりしません。元の66レースから時点別に何レース・何頭を除外したかと固定理由コードを報告します。

初期取得上限は合計5万行、読込予算180秒、SQL各60秒です。上限超過では一部の行だけで測定せず停止します。

## 指標の定義

市場確率は `p_raw=1/odds` をレース内で正規化したものです。控除・表示丸め・投票行動などを含む市場の相対的な重みであり、正しい実勝率であるとは仮定しません。V0.3には保存済みの温度T=2.0をそのまま適用します。

- Log Loss・Brier：従来と同じ馬単位二値。Log Lossは自然対数。市場・AI・一様予測を必ず同じレースと全出走馬で再計算します。
- 予測1位的中率：従来と同じく、同率1位に勝馬が含まれる場合は1/同率頭数を加算します。勝馬順位は同率の平均順位です。
- 確率帯：0～1%、1～2%、2～5%、5～10%、10～20%、20～100%。下限を含み上限を含みません（最後のみ100%を含む）。モデルと市場を並記します。
- 予測/実勝率：平均予測確率を実勝率で割ります。勝数0や空の帯はnullと理由コードを保存し、0や無限大へ置き換えません。
- Spearman：レースごとに平均順位で計算し、算出可能なレースを等重みで平均します。定数ベクトルで算出不能な件数を分けます。
- 予測1位一致率：モデルと市場の同率1位は、それぞれ最小馬番を選ぶ固定規則です。的中率の同率配分とは区別して記録します。

## 保存物と結果の読み方

新しい `C:\Users\acbd5\AppData\Local\JraRacingAI\ml-v03\evaluations\<ID>` にだけ保存します。既存モデル・予測・台帳・精算結果は変更せず、実行前後の主要入力ハッシュが一致することを確認します。保存先には既存の同期フォルダー等の拒否処理を使います。

- `summary.json`：匿名の実測指標、校正、順位相関、対象・除外件数、時点、元成果物のIDとハッシュ。
- `report.md`：同じ匿名集計の簡潔な比較レポート。
- `raw_format_review.local.json`：本人の保存形式確認用。個別データを含むため共有不可。
- `selected_inputs.local.json`：実際に使ったレースキー・馬番・価格・時点をローカルに固定した再現資料。共有不可。

最後の標準出力は `summary.json` と同じ匿名集計です。`measurement_status=complete` は少なくとも1つの時点区分で元の全対象を測定できた状態、`partial` は部分集合だけ、`odds_unavailable` は全区分が未算出です。各区分の母数を必ず確認してください。

市場とV0.3の差は `market_minus_model_log_loss` に保存します。負ならその同じ対象では市場のLog Lossが小さく、正ならV0.3の方が小さい値です。約0.21との差も併記しますが、「約」の許容幅を後から作って合否を判定しません。小標本の点推定であり、収益優位や全条件での優劣を断定しません。次の検討はこの実測を見てから行います。
