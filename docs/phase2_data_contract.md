# Phase 2 LightGBM基準モデルのデータ仕様

文書日：2026-10-15（Asia/Tokyo）。契約案：`0.1`、状態：`proposed`。

Phase 2.0更新：[Version 0.1](version_0_1.md)を実装しました。本書の公式HR的中ラベル・決済ゲートは将来の正式契約として維持しますが、利用者の承認により、確定着順から作る明示的な暫定ラベルでLightGBMの学習・予測・確率評価を先行します。HR金額未確認はこの学習を止める条件にしません。DBテーブルの追加・変更はありません。実列は本人確認済みのローカル対応表だけを使います。

v0.1の実行契約は、全6列レースキー＋2桁馬番、RA/SE区分7、日付単位のtrain/validation/test、学習期間だけで決めるカテゴリ辞書、最低1日（既定7日）の過去結果遅延です。単勝は着順1、複勝は観測SE行数に応じた2/3着のrank proxyで、公式HRの的中ラベルとは区別します。取消等・未確定順位は不明ラベル。任意特徴量は未対応・未確認なら欠損にします。収益指標は公式金額契約未確認の間nullです。詳細は上記実行手順を参照してください。

`confirmed` は仕様と実構造・変換の両方が確認済み、`proposed` は設計案、`needs_confirmation` は追加確認、`prohibited_feature` は特徴量への使用禁止です。要件として合意した方針と実列の確認済み状態は区別します。

## A. 対象と確率

| 項目 | 状態 | 契約 |
|---|---|---|
| 対象 | proposed | JRA国内10競馬場。基本単位は1レースの1出走予定馬 |
| 券種 | proposed | 単勝・複勝の基準モデルを別の二値確率として設計 |
| 単勝確率 | proposed | 予測時点情報I(t)を条件に、通常の公式単勝的中対象集合に当該馬が含まれる確率 |
| 複勝確率 | proposed | I(t)を条件に、通常の公式複勝的中対象集合に当該馬が含まれる確率 |
| 条件付き母集団 | proposed | 当該券種が成立し当該投票が有効な標準的中評価母集団。返還・特払・不成立等の確率はこの基準モデルでは扱わず、別状態として未確定 |
| ラベル根拠 | needs_confirmation | HRの通常払戻の的中対象集合。着順だけで最終ラベルを確定しない |
| 同着 | proposed | 的中対象集合の複数要素を保持し、該当馬を各々1とする。単勝対象を1頭に潰さない |
| 複勝対象頭数 | needs_confirmation | 出走頭数・成立条件・同着などを公式仕様とHRで確認。常に3着以内というルールを採用しない |

標準的中のラベルは、通常払戻が確認できた有効な券種/投票だけで0/1を付けます。返還・中止・特払・不成立・発売なし・未解決は、0に置換せずラベルをNULLとし評価マスクを分けます。返還等が現実に起きる確率を無視した2値モデルだけでは、無条件の期待純利益が確定しないことを明記します。

## B. 予測対象・学習対象の除外

| 事象 | 予測時点の扱い（proposed） | 学習/標準確率評価（proposed） | 決済評価 |
|---|---|---|---|
| 取消・除外がt以前に公開済み | 予測・仮想購入対象から除く | 有効投票母集団外 | 買っていた過去投票があれば別台帳 |
| 取消・除外がtより後 | tの対象から事後情報で消さない | 当該券種の返還などを確認してマスク | 公式返還等として残す |
| レース中止 | t以前に既知なら購入しない | 標準ラベルを作らない | 購入済み票の公式処理を記録 |
| 同着 | t以前に予測不可能な結果 | 公式の複数的中対象を保持 | 対象ごとの公式払戻を使用 |
| 不成立・特払・発売なし | tで利用可能な発売情報に従う | 標準的中指標から分離 | 各別状態。勝手に通常払戻・返還へ統合しない |
| キー欠損・未確定マッピング・未解決結果 | 構築不可なら理由を記録 | 除外数・理由・率を公開可能な集計で記録 | 未解決を0円として埋めない |

予測対象集合は `as_of` の情報だけで決定し、事後の評価対象集合と別に保存する案です。欠損ラベルや除外の偏りを監査し、有利なレースだけ残す選別をしません。

## C. 時点管理

| 情報群 | 状態 | 利用条件 |
|---|---|---|
| 過去レースの確定成績 | needs_confirmation | 対象レースより前に終了し、t以前に確定/公開された版のみ。対象レース自身を含めない |
| 今回レースの出走前情報 | needs_confirmation | t以前に入手できた版、取消・変更の反映時点を確認 |
| 今回レースの結果・HR | prohibited_feature | ラベル照合・決済評価専用。特徴量ファイルへ入れない |
| 今回レースの最終/確定オッズ | prohibited_feature | 事前特徴量・購入判断に使用しない。依頼文のO1区分5は確定（月曜）オッズ |
| 時点が確認できるレース前オッズ | needs_confirmation | 保存履歴と発表/取得時点を確認した後、事前購入判断用に別入力として採用検討 |
| 時点が確認できない任意の列 | prohibited_feature | 名前やデータ作成日から利用可能時点を推測しない |

前日・当日・発走直前を別の `prediction_policy_id` として設定し、それぞれの締切時刻と許可情報を定義します。今回、具体的な締切時刻・秒数は決めません。発走予定変更や締切変更もtで既知の版を使います。

内部時刻はUTC、原情報のtimezoneと表示はAsia/Tokyoを保存する案です。`event_at`、`published_at`、`observed_at`、`ingested_at`、`feature_as_of` を区別します。`ingested_at`/作成日だけでは `published_at` を代用しません。

後日の訂正・マスタ更新を当時の行に上書きしません。履歴がなく当時の版を再現できない列は利用不可です。過去成績集計でも、レース終了時刻だけでなく結果の公開/確定時点を条件にします。

## D. 論理データセット案

次は論理フィールド名であり、実DB列名・DDLではありません。全項目の配置は `proposed`、原データとの対応は別途 `needs_confirmation` です。実データを含む出力は将来もOneDrive外に置きます。

| データセット | 主キー案 | 内容と制限 |
|---|---|---|
| feature_frame | 6列レースキー＋馬識別キー＋prediction_policy_id＋feature_as_of | 出走馬単位、許可された特徴量だけ |
| outcome_frame | 6列レースキー＋馬識別キー＋結果版 | win/place label、評価マスク、公式結果状態、根拠の仕様版。特徴量としてjoinしない |
| pre_race_odds_frame | 6列レースキー＋券種＋対象＋公開時点＋版 | 予測時点の購入判断専用。O1区分5を禁止 |
| settlement_frame | 6列レースキー＋券種＋投票対象＋決済版 | HRの正規化済み公式的中/通常払戻/返還/特払等。Phase 1.1では未生成 |
| decision_ledger | prediction_run_id＋仮想投票ID | 判断時刻、確率、当時のオッズ参照、購入/見送り理由、単位数、資金制約 |

| feature_frame項目 | 状態 | 定義/確認ゲート |
|---|---|---|
| 6列レースキー | needs_confirmation | 既存6列を個別保持。型・桁の照合後に正規化規則を固定。曖昧な文字列連結をキーにしない |
| horse_identity | needs_confirmation | 馬マスタとの安定した識別。馬番はレース内投票対象であり、馬個体キーと自動同一視しない |
| runner_number | needs_confirmation | 当該レースの投票対象との対応。桁・返還馬番との関係を確認 |
| feature_as_of / policy_id | proposed | 予測締切・時点方針。feature_as_ofを過去時点へ偽装しない |
| feature columns | needs_confirmation | registryで許可された対応・型・利用可能時点だけ採用 |
| source/spec/build_version | proposed | ソース範囲・仕様版・コード版・カテゴリ辞書版・データ期間の再現性を記録 |
| freshness/availability state | proposed | unavailable/not_applicable/invalid/unmappedを欠損理由として区別 |
| win_label / place_label | needs_confirmation | outcome_frame側で公式対象集合への所属0/1/NULLとscore maskを管理 |

## E. 欠損・カテゴリ・過去走・更新

| 設計項目 | 状態 | 方針 |
|---|---|---|
| 数値欠損 | proposed | 未観測・該当なし・不正・初期値を区別した後NULL/NaN。0の意味が確認できない値を0埋めしない |
| カテゴリ | proposed | コードは文字列として桁を保持。学習期間だけで辞書を作り、未知/欠損を別状態で扱う |
| target encoding | proposed | 初期は使用しない。追加する場合、過去限定/学習内の時系列OOFで構築 |
| 過去走参照 | proposed | 安定馬キーで対象より前かつt以前に利用可能な確定版を参照。日付だけの同日比較が曖昧なら除外 |
| 集計窓・休養期間 | proposed | 過去N走/一定期間等は検証期間で設計し凍結。休養の時間差も正しい実開催時刻との対応を確認 |
| 騎手/調教師集計 | proposed | 当該人物の過去データのみ。累積値の事後更新や未来ラベルを使わない |
| 更新 | proposed | 訂正の新しい版を追加し、構築時点の原版を記録。既存実DBは読み取りのまま |
| 重複 | proposed | 出走馬×予測policy×時点を1行。重複を先頭行で黙って除去せず原因・版を確認 |
| ラベル結合 | proposed | 結果/決済とキーで1対1を検証。同着の複数対象は異なる馬に帰属、joinで水増ししない |
| 漏洩テスト | proposed | 未来にだけある架空レコードを追加してtの特徴量が変わらないこと、HR/O1確定値が混入しないことを将来テスト |

実装段階では型・値域・一意性・時点・データ期間・除外理由の検証を行います。Phase 1.1のテストは監査と方針表だけであり、feature_frameの構築や未来不変性のテストは未実装です。

## F. 分割・評価との接続

分割年は年別収録状況・HR対応・特徴量履歴の確認後に提案します。固定の分割年をこの段階で採用しません。同じレースの馬はすべて同一分割に入り、時間順で学習→検証→未使用最終テストに進みます。詳細は [backtest_policy.md](backtest_policy.md)。

Log Loss、Brier Score、校正と、仮想購入の回収率・純損益を別に評価します。単勝の確率和を常に1、複勝の確率和を常に3とする強制正規化は採用しません。同着・払戻対象頭数を含むターゲット定義に合わせたレース単位診断を行います。

## G. Phase 2開始ゲート

| ゲート | 状態 | 完了に必要な根拠 |
|---|---|---|
| キー・出走馬母集団 | needs_confirmation | 馬キー・馬番・区分・取消/除外・版の対応、RA/SE/HR集合の解釈 |
| HR変換 | needs_confirmation | 仕様版、実列・繰返し・単位・特殊値・返還等の対応 |
| 時点情報 | needs_confirmation | 予測policyの締切、公開時点/履歴、当時の利用可能性 |
| 特徴量採用 | needs_confirmation | registryの物理列・時点根拠をconfirmedに昇格。未確認列は採用しない |
| 事前オッズ | needs_confirmation | 使用可能な時系列履歴の保有。O1区分5しかなければ事前EV評価は開始不可 |
| 分割と資金方針 | needs_confirmation | 収録期間から分割年を決め、検証/最終テスト、資金・損失上限を凍結 |
| 実装承認 | needs_confirmation | 利用者が実監査・仕様を確認してPhase 2の開発を承認する |

レース前オッズが確認できなくても、適切な特徴量とラベルが確定すれば確率モデルの検証だけを別途計画できます。その状態で過去の購入判断・月間期待利益を検証できたとは主張しません。
