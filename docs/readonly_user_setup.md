# 専用読み取り専用ユーザーの準備（未実行）

この資料のSQLはロール・権限を作成する管理者作業です。**今回の承認範囲外であり、Codexは実行していません。** 監査ツールは参照SQLのみを使用し、このSQLファイルを読み込みません。

1. 既存の読取ロールがないか、管理者がPC上で確認します。同名ロールがある場合は使い回さず、所有権・メンバーシップ・実効権限を調査します。
2. 別途承認後、PostgreSQL公式ZIPを展開した実際の `bin\psql.exe` またはA5 Mk-2で `pckeiba` に管理者として接続します。Codexへパスワードを共有しません。
3. [readonly_user_setup.sql](readonly_user_setup.sql) を読み、対象DBとスキーマを確認して手動実行します。実テーブルの内容変更、既存所有者やPUBLIC権限の変更は含みません。
4. パスワードはpsqlで `\password jra_audit_reader` と入力し、非表示プロンプトで設定します。パスワード入りSQL・コマンド・ファイルを作らないでください。A5のSQL履歴へパスワードを残す方法は使わないでください。
5. 新しいロールで本ツールの `schema --execute-local` を実行します。`postgres` 接続はプログラムが拒否します。

読取ユーザーはCONNECT・USAGE・既存publicテーブルのSELECTのみを明示付与します。監査側では、接続開始前からread-only、実トランザクションのread-only/isolation検証、実効書込・所有権・管理権限の拒否を組み合わせます。

PUBLICや所属ロールからCREATE/書込権限を受けるDBでは、専用ロールでもプログラムが拒否する場合があります。その場合は、管理者が既存利用者への影響を調査してから別途権限設計を見直してください。本ツールは権限を取り消しません。

新しい表へのSELECT権限は自動付与しません。JRA-VAN取得後に表が追加された場合は、管理者が対象を確認して付与します。シーケンス権限は監査に不要です。RLSを迂回する権限も付与しません。

外部通信禁止のため、`pg_hba.conf` の対象ローカル接続が外部ディレクトリ/Kerberos等に依存せず、ローカルのパスワード認証を使うことも確認してください。変更が必要なら別途承認が必要です。
