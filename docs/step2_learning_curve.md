# STEP 2 V2：学習量の効果を測る

旧V0.3・T=2.0・10月17日の予測と購入/精算台帳を保持し、同じ特徴量を使う単勝モデルを新しいIDで保存します。既存の朝タスクへ切り替えません。馬場状態・過去走破タイムの無効化も維持します。

比較計画は、性能を見る前にOneDrive外の `ml-step2/evaluations/<収集ID>/plan.json` に固定します。今回は既存の結合特徴量上限50万行に収まる、月初始まりの最大窓を採用しています。DB全体の全量を学習したと表示しません。

- 履歴：2015-07-02以降。全窓に共通の履歴開始日と7日遅延。
- 学習：2016-07-01～2024-11-30の有効レースから、直近144/500/1,000/2,000/5,000/最大の入れ子窓。
- 早期終了：2024-12-08～12-28。
- 温度校正：2025-01-11～02-02。
- 主評価：2025-03-01～05-31。
- 既知参考評価：2025-02-15～16。未知の最終評価とは呼ばない。

教師データは全頭の着順が分かり単独勝馬が存在するレースに限定します。過去走参照には、既存の定義で利用可能な確定結果を使います。履歴参照専用期間や間隔期間のレースを学習ラベルへ混ぜません。

特徴量キャッシュは `ml.features.build_features` の出力を一度生成して窓ごとに参照するだけです。新しい特徴量や計算上の定義変更はありません。キャッシュを使わない従来呼出しはそのまま使用できます。`model.fit_models` に実行ラウンドの記録を追加しています。

最大100ラウンド・早期終了20・既存LightGBM設定・seed42を主比較で共通にします。最大窓が100ラウンドまで実行された場合だけ、上限を300へ変える参考実験を別記します。T=2固定と既存候補0.75/1/1.25/2による再校正を必ず両方報告します。

レースを単位に1000回のペアード・ブートストラップ（seed20261018）を行います。再抽出後の全馬の損失和を頭数で割るため、従来の馬単位Log Loss/Brierと同じ指標です。レース平均損失の平均へ置き換えません。

## 再実行

本人PCのプロジェクトフォルダーで、収集済みスナップショットを使う学習・比較のみを再実行できます。追加認証・外部通信・ライブラリ導入はありません。

```powershell
& 'C:\Users\acbd5\AppData\Local\JraRacingAI\venv\Scripts\python.exe' -B '.\scripts\run_step2_local.py'
```

再実行でも新しい評価ID・モデルIDを作り、元データや旧モデルを上書きしません。実行結果は `%LOCALAPPDATA%\JraRacingAI\ml-step2\evaluations\<評価ID>` の `run.json`、`report.md`、`learning_curve.csv` に保存します。モデルは既存 `ml-v01/models/<新ID>`、予測と2系列のpolicyも既存のローカル保存規則を使います。選択レースキーは各モデル内の `training_selection.local.json` にのみ保存します。

学習曲線のSVG/PNGは、既存のデスクトップ付属PythonのReportLabチャートで生成します。ML用venvへの追加インストールは不要です。

```powershell
& 'C:\Users\acbd5\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -B '.\scripts\plot_step2_curve.py' '<評価フォルダーの絶対パス>\run.json'
```

確定O1の市場確率は事後参考として別集計します。取得できないレースは補完せず、モデル同士の主比較と市場共通部分を区別します。旧V0.3と新窓では学習時期・履歴範囲が異なるため、データ量の効果は共通条件の入れ子窓間の比較を重視してください。
