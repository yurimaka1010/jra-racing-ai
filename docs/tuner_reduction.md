# Tunerによる有限の段階的特徴量削減

既存39特徴量TunerモデルAを保持し、指定7項目を除いた32項目から24項目まで1列ずつ減らします。
各構成は元の固定初期パラメータから同じ4段階×2試行で開始し、前構成の最適パラメータを流用しません。
次に削る列は当該モデルの保存木のGain最小列で、同値は元の列順です。

最大9構成×8 LGBM fit＋Boruta最大20 RF fit＋C最大8 LGBM fit＝100実fit。
失敗も計数し、追加refit・自動リトライ・結果を見ての予算追加はありません。
CPU4、親と子孫のprivate memory12GiB、全体30分。共通research-training.lockを使用します。
Windows GetSystemTimesで実負荷を測り、各fit前に85%超なら待ちます（最大90秒）。

学習・早期終了・較正・評価は既存の2022〜2025年キャッシュを再利用します。
特徴量生成・カテゴリ辞書・欠損処理は変更せず、既存matrix出力から列を選びます。
新形式はbase_feature_specとselected featuresを別々に保存し、旧契約のFEATURESやローダーを変更しません。

温度と特徴量数は2024年11〜12月の同じ開発検証窓で選びます。
この窓は温度の当てはめにも使うため、未使用較正評価・独立検証とは呼びません。
39列を含む最小レースLog Lossから0.002以内の構成では列数の少ないものを選び、
その候補Bを凍結してからBorutaへ進みます。

Borutaはtrain-onlyのone-hot/数値中央値を使用。max_iter21（最大20RF）、64木、深さ5、perc100、alpha .05、two_step=True。
confirmedの展開列が1つ以上あれば、その元特徴量をCに採用します。
このルールは「元特徴量の全水準がconfirmed」とは異なります。
CのLightGBMは元のnativeカテゴリ列へ戻すので、A/B/CのLightGBM入力変換は同じです。
tentativeを昇格しません。confirmed0ならCを作らず、perc等の再調整案は記録にとどめます。

全候補凍結後に初めて2025年の評価ラベルを読みます。
比較は既存A39、事前指定の32項目、B、Cだけ。2025年は再利用済み開発比較で、未使用最終テストではありません。
選択に使わなかった構成の2025年成績を後から探索しません。
確率品質・校正・時間を記録し、ROIや購入条件は扱いません。
H・Stage7・朝7時タスク・2026年封印期間は変更・利用しません。
