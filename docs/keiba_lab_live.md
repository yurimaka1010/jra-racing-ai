# KEIBA LAB：PC内の4モデル自動表示・D39結果の探索閲覧

既存のSites版・64行CSV連携は変更しません。自動連携は同じPCのループバック版 `http://127.0.0.1:8767/` です。クラウドにJRAデータを置かず、外部CDN・外部API・LAN待受も使いません。通常の利用にCSV取込は不要です。

## 起動

プロジェクトの `start_keiba_lab_live.cmd` をダブルクリックします。既に起動中なら同じサーバーを使い、重複起動しません。

```powershell
& 'C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe' -NoProfile -ExecutionPolicy Bypass -File '.\scripts\keiba_lab_live.ps1'
```

PostgreSQL・PC-KEIBAの通常更新と、既存4モデル記録器が必要です。既存DPAPI資格情報をPC内で読みます。パスワードをコード・引数・ログへ保存しません。閲覧サーバーは記録器を起動・変更せず、新しいWindowsタスクも登録しません。既存の朝7時・Stage 7・4モデル自動起動タスクは維持します。

PCを再起動・ログオフした場合は再度このランチャーを開きます。PCが起動したままなら背景で稼働し、画面を閉じている間のDB結果ポーリングは行いません。

## 画面と更新

- 最初は「現在の参考予想」：既存 `dry-run-four` が保存したD39系3モデルの出馬表予想を表示。新旧D39・対照型の同じ固定モデル・温度で、結果を参照せず生成した別枠予想です。2026-10-24 09:10:04生成で36レース・468頭・1,404行を確認。参考予想をT−10記録や結果評価の母集団には入れません。
- 参考予想の生成時刻は画面上部に明記。15秒ごとに新しい保存版を確認する機能であり、15秒ごとに推論をやり直す機能ではありません。Hを異なる時点の入力で代用推論しません。
- `/`：旧D39・新D39・D39対照型・Hの保存済みT−10予想。各馬の順位・勝率、本命の一致・相違、モデルID・温度・時刻・保存元SHA-256を表示。15秒周期（保存ファイル再検査は最大10秒キャッシュ）。
- `/results`：D39系3モデルだけの着順・的中状況・固定済み仮想購入の精算。15秒周期で表示を更新し、DB結果は最大30秒キャッシュ。共通3モデル集合による記述集計を表示。Hの結果や指標は返さず計算もしない。
- 開催日「当日（自動）」は日本時間の日付変更に追従。10/24・25を明示選択して閲覧することも可能。
- 馬名は対象完全キーに限定したSEの馬番・馬ID・馬名だけのSELECTから表示用に取得。予測には使わず、未取得や不整合は補完しない。

主力Hの画面は予想のみ。結果画面へHの確率・順位・台帳を渡さず、D39結果をHと横並びにした表や中間成績を作りません。Stage 7の保存領域・結果は読みません。

## 対象と保存

対象日は今回承認された **2026-10-24 / 2026-10-25** に固定。それ以外（2026年1〜9月を含む）のAPI要求はデータ取得前に拒否します。元の記録は `d39-generation/evaluations/86ed126ffc8f4e2e85c8740eacf941f0/forward-four-sealed/YYYY-MM-DD/races/` だけを読みます。乾式試験・再演・受領記録のない予想を発走前予想に昇格させません。

新しい出力は `%LOCALAPPDATA%\JraRacingAI\keiba-lab-live\<新ID>\`：

- `authorization.json`：D39週末探索閲覧の承認範囲、H予想のみ、正式21週条件維持を記録。
- `fixed-predictions/`：最初に検証した各モデルの予想とハッシュ。上書きしない。元が後に変われば前の表示を保ち、結果評価から外す。
- `reference-predictions/`：別枠の出馬表参考予想。元のdry-run識別子・ハッシュを保持し、同じ識別子の書換えは拒否する。
- `result-versions/`：D39のみの結果更新を別ファイルへ保存。
- `view-history/`：結果画面・CSVを取得した日時、対象日、D39モデル、対象件数を毎回記録。自動更新による閲覧も含む。
- ルートの`current.json`と`service-<id>.log`：起動状態と固定コードのみ。SQL・認証情報・生行をログへ出さない。

既存の正式21週評価コード・凍結条件は変更しません。一方、今回のD39中間閲覧は別記録に残るため、D39について「21週終了まで結果を一度も見なかった」という解釈はできません。Hの封印は維持します。モデル選択・Tuner・再学習・購入条件変更は行いません。

## 着順・払戻の採用

全6列レースキー＋馬番＋馬ID＋全頭集合を検証。月曜成績SE7は着順を表示可能。全馬速報SE5/6は、確認済み通常HRと勝馬が一致する場合だけ採用し、月曜成績とは別の根拠を明示します。一部速報SE3/4は採用しません。

払戻は既存の本人確認済み円/100円プロファイルと `win_sim.settle_saved` のHRデコーダーを再利用。HR1（公式仕様で払戻金確定速報）/HR2（月曜成績）の単一通常保存版のみ。特殊・欠損・複数版・勝馬不整合は未精算です。SE7の着順だけ確認できた場合、着順表示を止めずに払戻を保留します。

仮想購入は保存済みD39台帳の選択馬だけを再利用（EV5%以上・100円・最大1点）。オッズから払戻を作りません。未精算を0円の損失とは扱わず、購入0件のROIは算出不能と表示します。

結果CSVは既存の25列を再利用し、`evaluation_kind=D39_weekend_exploratory` とします。従来SitesのStage 6 CSV受入口の封印ガードは緩めないため、週末CSVを従来入口へ無理に読み込む運用にはしません。

参考予想を新しく生成する場合は、既存の次のコマンドを一度実行します。正式記録器を変更せず、新しいdry-runフォルダーへ保存します。開催後のレースを新規の発走前予想に作り替えません。25日も既存4モデル記録器の起動時試験が保存できれば、自動的にその日の参考予想が表示されます。

```powershell
& 'C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe' -NoProfile -ExecutionPolicy Bypass -File '.\scripts\d39_current.ps1' -Mode dry-run-four -RunId '86ed126ffc8f4e2e85c8740eacf941f0' -RaceDate '2026-10-24'
```

## 失敗時と検証

読取ユーザーの同時接続上限が1であることを実測しました。共通の`db_connection.read_only_session`にWindowsの共有mutex待機を追加し、同じWindowsユーザー・セッションの記録器と閲覧サーバーの接続を直列化します。DB側の接続上限・権限は変更しません。記録器は最大20秒待機、閲覧側は1.5秒で保留・次回更新へ回します。SQL・トランザクションの読み取り専用条件は維持。閲覧側SQLは2秒上限です。

2026-10-24 08:40に並行接続で4モデル記録器が停止したため、最初のT−10前に接続層を修正し、登録済みの4モデル・Stage 7タスクを同じ定義で再起動しました。終了確認後の一時ロックだけを検証フォルダーへ退避。Stage 7の実装・計画・モデル・保存予測・結果や朝7時タスクは変更していません。両記録器の稼働、読取接続の直列化、モデル・計画のハッシュ不変を確認しています。同じ読取ロールを使う外部ツールはこのmutexを共有しないため、記録中の同時接続は避けてください。

未保存・遅延・名簿や予定変更・ハッシュ不整合は理由付きで表示。DB接続失敗時は保存予想の表示を継続し、結果は保留。HTTPは127.0.0.1:8767にのみ待受し、異なるHost・OriginやクロスサイトAPI要求は拒否します。許可したHTMLを開く通常のナビゲーションだけは可能です。

一度確認できたD39結果の取得に後から失敗した場合は、前回確認時刻と保留表示を付けて保持します。接続失敗を0的中・0払戻へ置き換えません。

架空受領記録・DBモック・UI集計テストを用意。実開催のT−10保存前は実予想を捏造せず、発走・公式結果到着前は実結果の一気通貫試験を完了扱いにしません。
